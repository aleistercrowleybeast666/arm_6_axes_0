# 总线负载与队列预算

标准 CAN 2.0B 扩展数据帧、8-byte payload：不含填充时约 **131 bits**（含 3-bit intermission）；可填充段约 118 bits，保守再计 29 bits，按 **160 bits/frame** 估算。

每轴 200 Hz、6 轴，若每个运动命令对应一条反馈：

```text
commands = 6 × 200 = 1200 frames/s
feedback = 6 × 200 = 1200 frames/s
nominal = 2400 × 131 / 1e6 = 31.44%
conservative = 2400 × 160 / 1e6 = 38.4%
```

约 61.6% 留给调度突发、参数帧、仲裁等；故障/错误帧及额外自发反馈不在以上稳态估算内。若电机固件自发反馈频率高于 200 Hz，需要按实测重新预算，不能直接照用该占用率。

RX static queue=32，能容纳 5 组完整的六轴突发另余 2 帧。在 1200 feedback/s 下约 26.7 ms 容量；这不代表允许任务阻塞该时长。bxCAN 硬件 FIFO 只有 3 帧，ISR 每次最多取 3 帧，记录 overflow/错误，协议在 CanRxTask 内解析。

TX static queue=64。六轴运动帧批量全收或拒绝；使能配置序列为 36 帧，可完整入队。CanRxTask 最长等待 1 ms 后泵最多 3 个邮箱；无独立 TX task。1 ms × 3 帧服务能力大于 1200 commands/s；配置突发排空约 12 ms，队首年龄 >20 ms 则锁存故障、撤销输出、丢弃队列并中止邮箱。

邮箱争用和队列满均有明确返回值，不阻塞控制任务。不保证六帧在物理总线上同时到达，也不能把批量入队解释为已执行。真实总线负载、最大 ISR 延时和控制抖动待硬件测量。
